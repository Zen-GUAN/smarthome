# 巴法云(bemfa) MQTT 桥接 Home Assistant 完整实操

把 HA 的 MQTT 接入直连巴法云，打通米家/小爱语音控制。本文是踩坑后验证可跑的
完整流程（2026-09 实战）。

## 核心难题：client_id

巴法 MQTT 强制 `client_id = 用户私钥`（控制台获取的32位hex）。实测：

- client_id=私钥 → CONNACK 接受
- client_id=其他任何值 → return code 5（未授权），username/password 填什么都不救

而 HA 的 MQTT 集成：

- 配置流表单只有 broker/port/username/password 字段，没有 client_id；
  提交时带多余字段直接 400
- 配置流会先试连 → 随机 client_id 被巴法拒 → cannot_connect → 根本建不了条目
- 选项流也没有 client_id，建好条目后无法补填

结论：唯一路径 = **storage surgery**（停 HA → 改 core.config_entries → 起 HA）。

## 实操步骤

### 1. 裸 socket 验证私钥/连通性（推荐，别用paho，轻量环境没装）

MQTT 3.1.1 CONNECT 报文：`\x00\x04MQTT` + flags + keepalive + client_id。
收到 CONNACK `\x20\x02\x00\x00` = 成功；第二字节非 0 = 被拒。

⚠️ 用私钥连接成功后别恋战：同一私钥重复连接会把 HA 踢下线（HA 会自动重连，
但别并行测试）。

### 2. 先建一个"占位"MQTT条目

配置流校验必须过，所以先指向接受任意 client_id 的公共 broker（如
broker.emqx.io:1883）：

- REST `POST /api/config/config_entries/flow`，body `{"handler":"mqtt"}` 拿 flow_id
  （注意：websocket 的 config_entries/config_flow 是 unknown_command；
  REST `/config/config_entries/config/flow` 是 404，正确入口带 /api 前缀）
- 再 POST `.../flow/{flow_id}`，字段**平铺**（包成 {"data":{...}} 会 400）
- ⚠️ 建条目前先确认 discovery 关闭！公共 broker 上 homeassistant/# 全是
  别人家的设备，discovery 开着会瞬间捡一堆垃圾实体（实测捡了17个）

### 3. storage surgery

文件：HA 配置目录下 `.storage/core.config_entries`（root 属主，容器内路径
/config/.storage/...，宿主机按实际 docker volume 映射，写必须 sudo）。

流程：停 HA 容器 → 注入 → 起 HA（全程 1-2 分钟）：

```python
import json, shutil
p = '/config/.storage/core.config_entries'   # 按实际路径
shutil.copy(p, p + '.bak')                    # 先备份
d = json.load(open(p))
for e in d['data']['entries']:
    if e['domain'] == 'mqtt':
        e['data']['broker'] = 'bemfa.com'
        e['data']['port'] = 9501
        e['data']['client_id'] = '<32位私钥>'
        e['title'] = 'Bafa Cloud'
json.dump(d, open(p, 'w'), ensure_ascii=False, separators=(',', ':'))
```

**执行方式的天坑**：`ssh "echo 密码 | sudo -S python3 -"` 且脚本走 ssh stdin
= 静默失败（密码和脚本共用 stdin，python3 读到 EOF 空脚本，exit 0 无输出！）。
正确姿势：

1. 先把脚本落盘（如 `ssh host 'cat > /tmp/inject.py'`）
2. 再 `echo 密码 | sudo -S python3 /tmp/inject.py`
3. 成功标志 stdout 有注入计数；失败立刻回滚备份并起 HA

### 3.5 两种路径：改现有条目 vs 插入全新条目

**路径A（改现有占位条目）**：键集完整，最省事，推荐。

**路径B（删掉重建/插入全新条目）**：先 DELETE
`/api/config/config_entries/entry/{entry_id}`，再往 entries 数组 append 新 dict。
⚠️ 新版 HA 对新条目有完整键集校验，缺键直接 KeyError 崩溃循环（HA 起不来）：

- 必需键（缺一不可）：`disabled_by`(None), `minor_version`(1), `subentries([])`，
  加上常规的 entry_id/domain/title/data/options/pref_*/source/unique_id/
  version/created_at/modified_at/discovery_keys
- 最稳做法：拿同文件里任一现有条目当键模板，缺的键按类型补默认值
- 崩溃症状 = 容器反复重启 + docker logs 看到 KeyError: 'disabled_by'

### 匿名会话签名（排障必读）

随机 client_id + 无账密 → 巴法 rc=0 接受但算匿名黑户——**订阅/发布全被静默
丢弃，HA 日志干干净净零错误**。如果"控制台 topic 显示离线 + HA 无报错 +
推消息自动化不触发"，就是它。

控制台"离线"的真义 = 该 topic 没有任何有效订阅者（匿名订阅不算数）——这是
判定 HA 侧订阅是否生效的最可靠信号。

⚠️ 巴法规则实测：client_id=私钥 且 username/password **全空** = 唯一可用组合；
随机clientId+账密 = rc5 拒绝；配置流 username/password 填空字符串也会被拒
（会发出空 username flag）。

### 4. 验证连接

- 条目 state=loaded（REST config_entries/entry）
- `docker logs --since 10m <HA容器> | grep -i mqtt` → 看到
  "MQTT client initialized, birth message sent" = 已连上（birth 只在 CONNECT
  成功后发）
- 自动化触发器自动挂载（日志 "Initialized trigger ..."），不用手动 reload

## 巴法 API 速查（实测）

| 用途 | 调用 | 备注 |
|---|---|---|
| 查消息/存在性 | GET `apis.bemfa.com/va/getmsg?uid=私钥&topic=X&num=1&type=1` | ⚠️**必须同时带 num 和 type**，缺任何一个都返 10002 假象。10002≠一定不存在。**可靠的topic存在性检查=postJsonMsg**：code 0=存在，40004=不存在 |
| 推送消息 | POST `apis.bemfa.com/va/postJsonMsg` `{"uid","topic","type":1,"msg":"on"}` | type: 1=MQTT/3=TCP；40004=topic不存在 |
| 查在线状态 | GET `apis.bemfa.com/va/online?uid=&topic=` | |
| 列topic | `vb/api/v2/allTopic` | 不好用，别指望 |

⚠️ getmsg 只留 HTTP API 推的消息，米家→巴法的 MQTT 下行指令不留档。
验证小爱链路是否通，唯一可靠依据 = HA 接收自动化的 last_triggered。

## topic 创建规则

- **没有任何创建 API**（官方流程 = 控制台手动建）
- topic 名只允许字母和数字，不允许下划线
- 名称一字不差 + 类型后缀要对（灯002/空调005，后缀错米家同步就不对）
- 控制台建 topic 时协议选 **MQTT**（选TCP会走专用通道，HA收不到）

## 验收方法论（重要）

- **e2e 只认 last_triggered，别看设备状态**——设备状态可能巧合一致，
  触发器没 fire 的假阳性真实发生过
- 推 payload "ping"（非 on/off）可以安全测链路，不会动设备
- last_triggered 是 **UTC**，北京时间 = UTC+8；写时间阈值用动态
  UTC now-N分钟当清零点，写死北京时间小时数会全盘误判
- HA 重启后自动化挂载 + MQTT 连接要等 2~3 分钟，推 ping 太早 = 白推
  （消息不补发）

## 订阅时序坑

topic 在 HA 已连接之后才于控制台创建 → 巴法不会向已有连接投递该 topic 的
消息（静默丢弃，与匿名会话症状同款：无报错、自动化不触发）。

`automation.reload` 重载自动化**不会**真正重新 SUBSCRIBE，唯一修法 =
重启 HA 容器让 MQTT 全新连接。**每批新建 topic 后必须重启 HA 再验证**。

## 批量生成自动化

参考 `scripts/gen_bemfa_automations_v2.py`：维护设备表
(key, 中文名, topic, 实体, kind)，按模板生成收/发两条自动化追加进
automations.yaml，生成后先 YAML safe_load 校验、失败自动回滚备份再 reload。

⚠️ 合并组（多实体 target）模板里必须含 `entity_id:` 键行（直接把列表挂
target 下会校验失败、自动化静默 disabled，症状 = state unavailable +
日志 "could not be validated"）。

## 幽灵实体清理

批量改 automations.yaml 重载后，被删自动化会残留 unavailable 幽灵实体，
REST 无注册表删除端点，走 websocket `config/entity_registry/remove`
（注意是 remove，delete 是 unknown_command）。

## QPS 限流

免费版共享服务器有 QPS 限制，快速连续语音指令会触发设备"临时离线几秒"，
小爱播报离线类错误。根因分析与复现脚本见 `docs/03-巴法QPS离线调研.md`。
