# 路线图：ESP32 蓝牙设备接入 与 Siri 控制渠道

> 状态：**规划中，未实施**。本文记录选型结论、链路设计与验收标准；
> 实施后按仓库惯例补充踩坑实录（参考 docs/02、docs/03 的写法）。

────────────────────────────────────────────────────

## 方向一：ESP32 蓝牙接入（窗帘等 BLE 设备）

### 目标

把 BLE 窗帘电机等蓝牙设备纳入 HA 统一控制，并经巴法桥接打通小爱语音
（"打开窗帘" / "窗帘到50%"），复用现有"双自动化防回环"模式。

### 选型与链路

ESP32（推荐 C3/S3，BLE 5.x，需与 Wi-Fi 共存）跑 ESPHome，以 **bluetooth_proxy**
（active 模式，可回连控制而不只是嗅探）作为 HA 的蓝牙代理。设备侧按生态三选一：

| 设备生态 | 接入路径 | 本地化程度 |
|---|---|---|
| SwitchBot 窗帘机器人 | HA 官方 SwitchBot BLE 集成 | 纯本地（最顺） |
| 涂鸦 BLE 窗帘电机 | Tuya BLE 集成（需涂鸦云账号辅助配对） | 本地控制 + 云辅助 |
| 米家 BLE（如杜亚米家版） | 米家云，或 xiaomi_ble（支持型号有限） | 云为主 |

链路：小爱 → 米家/巴法（**009 窗帘**）→ HA cover 实体 → ESPHome BLE → 窗帘电机
（009 类型后缀约定见 docs/01，正好为此预留）

### 阶段拆解

1. **代理打通**：ESP32 烧录 ESPHome + `bluetooth_proxy: active`，HA 蓝牙栈确认代理在线；
   先拿一台便宜的 BLE 开关/传感器验证覆盖与回连，别一上来就买窗帘电机
2. **设备入 HA**：窗帘电机接入为 cover 实体，本地实测开/停/位置
3. **巴法桥接**：控制台建 009 topic（字母数字命名），按
   `config/automations-template.yaml` 生成 cover 版收发自动化；
   payload 约定 `on` / `off` + 百分比，出站继续走 `<topic>/up` 防回环
4. **语音验收**：复用 docs/02 的验收方法论（推 ping、只认 last_triggered）

### 已知风险

- ESPHome active 代理同时回连设备数有限（约 8 台），窗帘电机多时需多代理分布式摆
- 2.4G Wi-Fi 与 BLE 共存会互相干扰；代理要摆在窗帘电机附近（电机一般靠窗，
  注意与 NAS 的距离），信号弱会表现为"看得见连不上"
- 米家 BLE 本地化程度因型号差异大，**买前先查 HA 兼容列表，别先买后接**
- 巴法 009 类型对小爱侧的百分比语义需实测（部分固件只认开/停）

### 验收标准

- 断外网：本地链路（HA → BLE）仍可控制
- 语音："打开窗帘" "窗帘到50%" 触发接收自动化 last_triggered 实时变化；
  位置误差实测记录（来回跑几次取偏差范围）

## 方向二：Siri 控制渠道

### 目标

不新增设备，让 Siri 直接控制已有 HA 实体，与小爱形成双语音入口、互为备份。

### 选型：HA 官方 HomeKit Bridge 集成（唯一推荐）

- 纯本地局域网（mDNS），不依赖任何云；延迟预期 0.5~1s，优于小爱链路（1~3s）
- 远程控制走 HomeKit hub（Apple TV / HomePod / 常驻 iPad），无需公网暴露端口
- 与现有链路零冲突：同一批实体，小爱走巴法 MQTT，Siri 走 HomeKit，各自独立
- 官方集成、官方协议，无合规灰色地带

### 实施要点（按踩坑概率排序）

1. **Docker 网络是第一坑**：HomeKit 依赖 mDNS 发现，HA 容器必须 **host 网络**；
   bridge 模式下配对必失败（`docker-compose.yml` 默认 bridge，启用 HomeKit 前需改）
2. **bridge 有 150 实体上限**：HomeKit Bridge 必须 filter 白名单，
   只暴露灯/空调/窗帘等需要的实体，别把全部实体倒进去
3. **friendly_name 决定 Siri 识别率**：沿用巴法合并组的经验——
   语音命名带位置词全名（"主卧灯带"优于"灯带"）
4. 配对码仅在配对阶段有效；异常时在 HA 侧重置 HomeKit 配对重来即可

### 备选（了解即可，不作首选）

- iOS 快捷指令调 HA REST API：适合"回家模式"类组合指令，依赖远程访问方案（如 Tailscale）
- Nabu Casa 订阅：官方托管省心但收费，国内延迟未实测

### 验收标准

- iPhone 家庭 App 出现全部白名单实体，状态与 HA 实时一致
- Siri 中文指令（"打开主卧灯带"）实测触发，记录端到端延迟并与小爱链路对比
- 蜂窝网络下经 HomeKit hub 远程控制成功
- 关闭外网：局域网内 Siri 指令仍通（验证纯本地链路）

## 优先级建议

两个方向相互独立、可并行，互不阻塞。若二选一先做：

- **Siri 方向工作量小**（纯集成配置，一个晚上含踩坑），收益立竿见影，建议先做；
  唯一硬前提是手头要有 HomeKit hub（没有的话远程用不了，仅局域网可玩）
- **ESP32 方向需要硬件采购 + 烧录**，周期长，但做完之后 BLE 类设备
  （窗帘/传感器/门锁）都有了统一入口，属于打地基
